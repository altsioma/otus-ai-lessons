## 2. Контракт ответа агента

Создай zod-схему в отдельном модуле, например:

src/agent/response-schema.js

Используй контракт:

{
  "status": "success | error",
  "action": "create_task | get_task | update_task_status | get_task_stats | multiple | none",
  "data": <структурированный объект или null>,
  "errors": ["сообщения об ошибках"]
}

Требования:
- при success массив errors пустой;
- при error data должен быть null;
- schema должна быть совместима со structured output текущей установленной версии LangChain.js/OpenAI;
- не используй слишком свободную схему, которую невозможно преобразовать в JSON Schema;
- data должна поддерживать:
  - объект задачи;
  - статистику;
  - результат нескольких последовательных действий;
  - null;
- если нужны отдельные вложенные схемы и union, реализуй их аккуратно;
- экспортируй также функцию финальной проверки/нормализации результата перед выводом CLI.

## 6. CLI

Замени временную реализацию main.js полноценным CLI.

Поддерживаемый запуск:

Также:

npm run agent -- "покажи статистику задач"

Поведение CLI:
- соединяет все аргументы после имени скрипта в один пользовательский запрос;
- при отсутствии запроса печатает краткую инструкцию использования;
- загружает конфигурацию;
- проверяет OPENAI_API_KEY только перед созданием модели;
- создаёт агента;
- выполняет запрос;
- печатает только один финальный результат в JSON с отступами;
- отладочные логи tools могут идти отдельно;
- устанавливает ненулевой exit code для:
  - отсутствующего запроса;
  - отсутствующего ключа;
  - ошибки инициализации;
  - итогового status: error;
- не выводит stack trace пользователю по умолчанию;
- не выводит секреты.

API запускается отдельной командой `npm run api`. CLI не должен создавать второе независимое in-memory хранилище внутри себя.
